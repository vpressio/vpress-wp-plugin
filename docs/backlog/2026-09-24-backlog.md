# Vpress backlog — night shift 2026-09-24

Goal: make Vpress one of the best **open-source** data-visualization tools that is genuinely **integrated into WordPress**, not an admin app bolted onto it.

Each item below becomes a GitLab issue on `vpress/vpress-wp-plugin` and, when implemented, a merge request targeting `vue3-on-vpress`. Landscape research behind the priorities: vault note `reflections/research/vpress-dataviz-landscape-2026`.

Legend: **H** high (blocks safe install or real integration) · **M** medium (differentiators + quality gates) · **L** low (reach + housekeeping). Size is AI execution time.

---

## High

### H1 · Security: close the unauthenticated SQL-injection surface in the REST API
**Evidence.** `VPRESS_API_QUERY_CHART_DATA` (`/chart/query`) and `VPRESS_API_GET_DATASET_DATA` (`/dataset/data/*`) register with `permission_callback => '__return_true'`. `api/services/chart.php` builds `FROM {$body['dataset']}`, `GROUP BY f1.{slug}` and `WHERE {slug} IN ('...')` by string concatenation; `$wpdb->prepare($query)` is called with no arguments (a no-op). `api/services/dataset.php` escapes identifiers with `str_replace("'", '`', $wpdb->prepare(...))` and carries a hard-coded third-party endpoint (`hue.devf.la`).
**Scope.** (1) Resolve `dataset` through the `vpresscore_datasets` registry, never from the request; (2) validate every column slug against the table's real columns (`DESCRIBE`, cached); (3) whitelist aggregate functions; (4) bind all filter values with `$wpdb->prepare`; (5) keep `/chart/query` public but only for charts whose `permissions` is public, otherwise require `read`; (6) list routes return only public items to anonymous callers; (7) remove the Hue branch behind a `vpress_external_query_handler` filter; (8) PHP unit tests for the SQL builder (happy path + injection attempts).
**Done when** injection payloads in dataset, slugs and filter values are rejected with 400, and tests prove it. **Size:** ~40 min.

### H2 · Verify and lock chart rendering under Vue 3 with an end-to-end smoke test
**Evidence.** The 2026-07-30 migration converted 30 SFCs; build, lint and 15 unit tests are green, but no one has dragged a field onto an axis in the new stack. d3/dbox has never drawn a chart under Vue 3.
**Scope.** Playwright project under `admin/tests/e2e/`: log in as the seeded `vpress_e2e` user, open Vpress, pick the `ventas` dataset, drag `estado` → Eje X and `ventas` → Eje Y, assert `svg` bars exist, save, open `/chart/{id}` and assert the SVG renders publicly. Fix whatever breaks. Add the job to `.gitlab-ci.yml` (headless Chromium).
**Done when** the E2E passes locally against MAMP and the CI job definition exists. **Size:** ~45 min (plus fixes).

### H3 · Rebuild the public embed: a lightweight renderer and a server-rendered `<figure>`
**Evidence.** `includes/vpress-shortcode.php` outputs an empty `<div id="vpress-{id}">`; `public/vpress.js` is a 2023 spike fetching `http://localhost:8888/wp-json/vpress/v1/dummy/get/…`; `public/components/Chart.js` hard-codes `chart_id = 1`. The only working public surface is `/chart/{id}`, which loads the full admin bundle (`chunk-vendors.js` 1.7 MB) to draw one chart.
**Scope.** (1) `includes/class-vpress-figure.php`: `vpress_render_figure( $chart_id, $args )` returns `<figure class="vpress-figure" data-vpress-chart="ID">` with title, subtitle, placeholder, `<figcaption>`; used by the shortcode, the `/chart/{id}` page and the block (H5); (2) a second Vite entry `admin/src/embed.js` that bundles only d3 + dbox + the chart container (no Vuetify, no router, no Pinia), mounts on every `[data-vpress-chart]`, fetches `/chart/get/{id}` + `/chart/query`; (3) `/chart/{id}` becomes a proper themed page (header/footer) with the figure; (4) delete the dead `public/vpress.js`, `Chart.js`, `dboxjs/` copies.
**Done when** a post with `[vpress id="N"]` renders the chart without the admin bundle and `/chart/N` weighs under 400 KB gzipped. **Size:** ~90 min.

### H4 · Accessibility by default: text alternative, data table, keyboard tooltips
**Evidence.** SVG output has no `role`, `aria-label` or `<title>`; there is no data table; tooltips are mouse-only; colour is the only channel for series. WCAG 1.1.1 treats a chart as a complex image.
**Scope.** (1) Deterministic alt text generated in PHP from the chart config and the queried data: chart type, encodings, series count, max/min, direction of change for time series (`"Gráfica de barras de ventas por estado, 32 estados; el mayor es Nuevo León (1,240), el menor Colima (85)."`); (2) `<details class="vpress-data">` with a `<table>` (`<th scope>`) of the plotted data, collapsed by default; (3) `role="img"` + `aria-describedby` on the SVG wrapper, `<title>/<desc>` inside the SVG; (4) tooltips reachable by keyboard (focusable marks, Enter/Space to open, Esc to close); (5) palettes checked for 4.5:1 text contrast and a pattern/label fallback when series > 1. Applies to the figure from H3 and the editor preview.
**Done when** axe-core reports no critical violations on `/chart/{id}` and the alt text is asserted in the E2E. **Size:** ~60 min.

### H5 · Native block `vpress/chart` with live preview
**Evidence.** Insertion is a 2019 shortcode. Current WordPress guidance: client-side edit preview from REST data, server render for the front end; `ServerSideRender` is legacy.
**Scope.** `blocks/chart/` with `block.json` (apiVersion 3), `edit.js` (chart picker via `/chart/list`, live preview using the embed renderer from H3, alignment + caption toggles), `render.php` delegating to `vpress_render_figure`, `viewScriptModule` = the embed bundle. Register with `register_block_type_from_metadata`. Keep the shortcode as an alias. Add a "Insertar en una entrada" button in the editor that copies the block markup.
**Done when** the block appears under "Widgets/Vpress", previews live in the editor and renders the figure on the front end. **Size:** ~75 min.

### H6 · WordPress.org readiness: headers, readme, uninstall, Plugin Check
**Evidence.** Header `Version: 0.1.0` vs `VPRESS_VERSION '0.2.0'`; `Plugin URI: vpress.io` (domain lost); `Tested up to: 5.6` (WP is 7.1); `Requires PHP: 7.2`; `readme.txt` Spanish-only; `uninstall.php` removes nothing; `flush_rewrite_rules()` runs on every `init`; leaflet CSS loaded from unpkg (external assets fail Plugin Check); `admin/dist` is gitignored so a clone installs a broken admin.
**Scope.** Fix header + constant to `0.3.0`; `Tested up to: 7.1`, `Requires at least: 6.5`, `Requires PHP: 8.1`; bilingual `readme.txt` (EN primary, ES section) with real screenshots list and FAQ; `uninstall.php` drops `vpresscore_*` tables and every `vpress_*` table + options behind an "erase data" option; flush rewrites only on activation; vendor leaflet CSS locally; add a `bin/build-release.sh` that builds `admin/dist` into a distributable zip; run Plugin Check and fix every "Plugin repo" category error.
**Done when** Plugin Check "Plugin repo" is clean and a release zip installs on a fresh WP 7.1. **Size:** ~50 min.

### H7 · Internationalization of the PHP layer (English source, Spanish translation)
**Evidence.** Three i18n calls in PHP; strings hard-coded in Spanish; `languages/vpress.pot` stale.
**Scope.** Wrap every PHP-emitted string in `__()`/`esc_html__()` with text domain `vpress`, English as source; generate `vpress.pot`; ship `vpress-es_MX.po/.mo`; `load_plugin_textdomain`. (The Vue admin UI is M8.)
**Done when** a site in `en_US` shows English admin menus, notices, figure captions and error messages, and `es_MX` shows Spanish. **Size:** ~35 min.

## Medium

### M1 · Provenance by default: source line, licence, retrieved-at, JSON-LD
**Why.** The Data4 lineage is trust. No WP chart plugin treats source as a feature. `vpresscore_datasets.source` exists but is free text and never shown.
**Scope.** Add `source_url`, `license`, `retrieved_at` to datasets (dbDelta migration); editor fields; figure footer `Fuente: {source} · {license} · {date}`; chart page emits schema.org `Dataset` + `ImageObject` JSON-LD; `/wp-json/vpress/v1/chart/{id}/export.json` returns config + data + provenance. **Size:** ~40 min.

### M2 · Vpress Stories: scrollytelling block, free and native
**Why.** Flourish gates scrollytelling behind Enterprise; Datawrapper does not have it. The manifesto is "Stories do." This is the differentiator.
**Scope.** `vpress/story` (container, sticky figure) + `vpress/story-step` (rich text + chart state overrides: filters, highlighted series, title, chart type). Front end via the Interactivity API: IntersectionObserver marks the active step, the embed renderer applies the step's overrides with a transition. Editor: step list with a "capture current state from editor" helper. **Size:** ~120 min.

### M3 · Live data sources: CSV URL and Google Sheets with scheduled refresh
**Why.** Visualizer Pro's headline feature; Datawrapper's "live data". Vpress imports once and forgets.
**Scope.** Dataset `source_type` (`upload` | `url` | `gsheet`), `refresh_interval`; reuse the chunked import pipeline for the fetch; WP-Cron event + "Actualizar ahora" button; freshness stamp in the figure footer (ties to M1). **Size:** ~60 min.

### M4 · Theme-aware defaults and dark mode
**Why.** Only a native plugin can read the site's `theme.json`. SaaS embeds never match the site.
**Scope.** Default palette from `wp_get_global_settings()['color']['palette']`, typography from theme font families; `prefers-color-scheme` and `[data-theme=dark]` support in the embed; per-chart override remains. **Size:** ~40 min.

### M5 · Annotations: reference lines, highlighted points, notes
**Why.** Datawrapper's most-used editorial feature; absent here.
**Scope.** `annotations[]` in chart value (`line`, `point`, `range`, `text`), editor panel, dbox render hooks, exported with the chart. **Size:** ~75 min.

### M6 · Exports: SVG, PNG and CSV from every embed
**Why.** Journalists re-use charts in print and social; RAWGraphs and Datawrapper both ship SVG.
**Scope.** Figure toolbar (opt-in per chart): download SVG (serialize + inline styles), PNG (canvas rasterize, 2x), CSV of the plotted data; keyboard accessible. **Size:** ~35 min.

### M7 · Quality gates in CI: PHPUnit, Vitest, ESLint clean, PHPCS, Plugin Check
**Why.** Baseline is 15 Vitest tests, zero PHP tests, ESLint 2 errors / 730 warnings, CI = GitLab's generic Code-Quality template.
**Scope.** PHPUnit 11 (phar) with a bootstrap that stubs `$wpdb`/WP functions via Brain Monkey or a thin shim; `phpcs` with WordPress-Coding-Standards; ESLint to zero warnings; `.gitlab-ci.yml` stages: lint → unit (JS+PHP) → build → plugin-check → e2e. **Size:** ~50 min.

### M8 · Vue admin i18n (English UI, Spanish translation)
**Why.** The editor is Spanish-only; WordPress.org is global.
**Scope.** `vue-i18n`, extract strings from 30 SFCs into `en.json` (source) + `es.json`, locale from `wp_localize_script` (`get_user_locale()`). **Size:** ~60 min.

### M9 · Admin bundle diet and privacy cleanup
**Why.** `chunk-vendors.js` is 1.7 MB; leaflet/topojson/xlsx load for every screen; LogRocket ships in an open-source build (telemetry without consent).
**Scope.** Dynamic imports for map/xlsx paths; drop LogRocket (or gate behind an explicit filter); local leaflet assets; target < 600 KB gzipped for the editor. **Size:** ~40 min.
